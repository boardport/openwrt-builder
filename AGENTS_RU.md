# Паспорт проекта и регламент для AI-агентов: Сборщик OpenWRT

> **Проект:** BoardPort — OpenWRT Builder  
> **Организация:** [BoardPort](https://github.com/boardport) | **Репозиторий:** `boardport/openwrt-builder`  
> **Миссия:** Модульный сборщик прошивок OpenWRT на основе оверлеев для встроенных и legacy-устройств  
> **Целевая экосистема:** Встраиваемые аппаратные платформы, 4G/LTE-модемы, роутеры и SBC | **Лицензия:** [MIT](./LICENSE)  

---

## 1. Организация контекста искусственного интеллекта

Корневые файлы [`AGENTS.md`](./AGENTS.md) и [`AGENTS_RU.md`](./AGENTS_RU.md) служат базовым обязательным регламентом для всех AI-ассистентов.
Разработчики изолируют и настраивают вторичный контекст под свои инструменты:

- **Специализированные директории (`.(gemini|claude|cursor|continue|qwen|etc)/`):** Индивидуальный контекст конкретных ассистентов
  (промпты, навыки, отчеты, сессии). Полностью изолированы и исключены из Git (`.gitignore`).
- **Маршрутизация контекста:** Навигация внутри директорий организуется через `.{ai}/README(_RU).md` или `.{ai}/AGENTS(_RU).md`.
  Инструкции дополняют базовый регламент и имеют приоритет внутри своей директории.
- **Файл `.aiignore`:** Определяет ресурсы, строго исключенные из фонового сканирования и индексации
  (деревья сборки OpenWRT, кэши пакетов, бинарные образы, дампы). Доступ возможен только по прямой команде.

## 2. Архитектура и структура подмодулей

- **Корневой репозиторий-оркестратор:** `boardport/openwrt-builder` координирует сборочные окружения и слои адаптации оборудования.
- **Слои подмодулей (Submodules):**
  - `docker/` (`boardport/openwrt-docker`): Рецепты сборки контейнеров (`toolbox`, `toolchain`, `target`),
    Dockerfiles и кросс-компиляционные окружения.
  - `overlay/` (`boardport/openwrt-overlay`): Внешний аппаратно-зависимый оверлей (профили устройств,
    DTS-файлы, внешние модули ядра, системные патчи).
- **Чистота Git-отслеживания:** Деревья исходников апстрима (`/openwrt*`, `/linux*`), рабочие копии, собранные прошивки (`output/`, `volumes/output/`)
  и кэши загрузок (`dl/`, `volumes/dl/`) никогда не фиксируются в системе контроля версий.

## 3. Инструментарий автоматизации (Makefile)

Проект оснащен корневым мастер-`Makefile` и модульными задачами в `.make/`:

- `make help` / `make list`: Просмотр всех доступных команд автоматизации с описаниями.
- `make openwrt-build-toolbox`: Сборка базового Debian-образа с инструментами хоста.
- `make openwrt-build-toolchain [OPENWRT_ARCH=...]`: Сборка предскомпилированного кросс-тулчейна под указанную архитектуру.
- `make openwrt-sh-toolbox` / `make openwrt-sh-toolchain`: Запуск интерактивных контейнеров для разработки и отладки.
- `make openwrt-menuconfig`: Запуск конфигуратора меню OpenWrt внутри контейнера.

Подробная документация по подмодулям доступна в `docker/README_RU.md` и `overlay/README_RU.md`.

## 4. Стандарты форматирования Markdown

- **Правила оформления:** Форматирование регулируется `.editorconfig` и `.markdownlint-cli2.jsonc`.
- **Обязательная проверка линтером:** Команда `npx markdownlint-cli2 "**/*.md"` перед завершением работы должна возвращать `0 issues in 0 files`.
- **Зеркальная двуязычность:** Вся публичная пользовательская документация поддерживается параллельно (`*.md` на английском и `*_RU.md` на русском).

## 5. Стандарты Git и GitHub (`.github/`)

- Политики сообщества, шаблоны задач/PR и CI-пайплайны располагаются в [`.github/`](./.github/).

- **Правило фиксации изменений:** Создание коммитов разрешено **только по прямому подтверждению пользователя**.
